# The mental-math gate

ChatGPT, Gemini and Stream are locked until you pass a quick tables challenge.

## Rules

- **10 questions, only from facts already introduced to you**: facts you have answered at least once in the trainer, within your unlocked stage. Each challenge uses distinct facts, the order of the two factors is random, and ×1 facts are left out unless they're needed to reach 10.
- **With fewer than 10 introduced facts there is no challenge yet.** The page says how many you have and links to the trainer.
- **40 seconds** for the whole set, measured on the server from *Start* to submission.
- **At least 8 correct.** 8/10 at exactly 40.0 s passes.
- Fail either condition and you're denied; the next try is a brand-new set.
- A pass opens all three apps for **30 minutes**.
- The apps lock again on any of these: expiry, sleep/resume, reboot, a new login, a service restart, or `tables-gate lock`.
- Nothing is revealed until you submit. The answers and the timer exist only in server memory.

- **Your answers count as practice.** Each one goes through the same engine as the trainer and shows up as a *Gate challenge* session.

## Going to the challenge, and coming back

With the **Tables gate extension** (`deploy/extension/`) installed in the browser:

- **Opening ChatGPT or Gemini while locked sends that tab to the challenge**, the same way Stream does. After a pass, *Continue* takes you back to the page you asked for.
- **When access ends** (the 30 minutes run out, or sleep or `tables-gate lock`), every open ChatGPT/Gemini tab asks: *"Go back to the Tables app to unlock it for another 30 minutes?"* **OK** takes that tab to the challenge, and passing gives another 30 minutes. **Cancel** leaves the tab as it is: it can't load anything, and reloading it goes to the challenge.
- The extension only redirects. The gate proxy still refuses these hosts while locked, so removing the extension unlocks nothing.

**Without the extension**, the old fallback applies: the original tab shows "The proxy server is refusing connections" (a proxy cannot redirect an HTTPS site), and the challenge opens by itself in a new tab of the same browser, with a notification:
- At most once per app and browser every 3 minutes, so a background tab retrying can't flood you with tabs.
- Never while you already have the challenge open, and never in a browser whose extension checked in during the last 45 s.
- Set `GATE_AUTO_OPEN=0` in `tables.service` to turn it off.

You can always open the challenge directly at <http://127.0.0.1:5170/gate>, or from **Gate** in the app's menu.

### Installing the extension

Release Firefox only installs signed extensions, so sign it once as *unlisted* (private, never published on addons.mozilla.org). You need API keys from <https://addons.mozilla.org/developers/addon/api/key/>:

```sh
npx web-ext sign --source-dir deploy/extension --artifacts-dir web-ext-artifacts \
  --channel unlisted --api-key "$AMO_JWT_ISSUER" --api-secret "$AMO_JWT_SECRET"
```

Then force-install the signed `.xpi` through each browser's locked policy. The user can't disable or remove it, and it runs in private windows too:

- **Zen**: `deploy/zen/policies.json` already has the `ExtensionSettings` entry.
  ```sh
  D=/var/lib/flatpak/extension/app.zen_browser.zen.systemconfig/x86_64/stable
  sudo install -m644 web-ext-artifacts/*.xpi $D/tables-gate.xpi
  sudo install -m644 deploy/zen/policies.json $D/policies/policies.json
  ```
- **Firefox**: the policy is sealed by DeepWork. Unseal it (see *Changing the Firefox host list* below), copy the `.xpi` to `/etc/firefox/tables-gate.xpi` (`sudo install -m644`), and add this under `"policies"` in `~/.config/deepwork/policies.json`:
  ```json
  "ExtensionSettings": {
    "tables-gate@nebula.local": {
      "installation_mode": "force_installed",
      "install_url": "file:///etc/firefox/tables-gate.xpi",
      "private_browsing": true
    }
  }
  ```
  Then reinstall the policy as its `_comment` describes, and seal again.

Restart both browsers, then check `about:policies` and `about:addons`. To try the extension before signing, load `deploy/extension/manifest.json` from `about:debugging` → *This Firefox* → *Load Temporary Add-on* (it lasts until the browser restarts). After changing the extension, raise `version` in its manifest, then sign and install it again.

## What is protected, and how

| App | Hosts | Enforced by |
|---|---|---|
| ChatGPT | `chatgpt.com` | browser PAC → gate proxy `127.0.0.1:8898` |
| Gemini | `gemini.google.com` | browser PAC → gate proxy |
| Stream | `127.0.0.1:5180`, plus its player hosts `youtube-nocookie.com` and `googlevideo.com` | gate owns port 5180; the player hosts go through the gate proxy |

- **Firefox**: `~/.config/deepwork/study.pac`, generated by the sealed `deepwork` script (`GATED_HOSTS`). The root policy in `/etc/firefox/policies` locks it in.
- **Zen (flatpak)**: the root-owned policy and `gate.pac` in `/var/lib/flatpak/extension/app.zen_browser.zen.systemconfig/x86_64/stable/`, seen as `/app/etc/zen` inside the sandbox. Sources are in `deploy/zen/`.
- **Stream** listens only on the private socket `$XDG_RUNTIME_DIR/stream.sock` (mode 0600). The gate forwards to it while open and redirects to `/gate` while locked.

The gate proxy only *tunnels* traffic; it never decrypts it. It refuses every host that isn't on the list, and it cuts open tunnels the moment the gate closes. If the gate service is down, protected hosts **fail closed** (both browsers lock `network.proxy.failover_direct = false`). Every other site, and this app, keep working.

The host list exists in three places and must stay identical: `server.mjs` (`GATED`), `deploy/zen/gate.pac`, and `GATED_HOSTS` in `~/.local/bin/deepwork`. `tests/gate-pac.test.ts` checks the first two against each other. The extension's ChatGPT/Gemini hosts (`deploy/extension/gate-core.js` and its manifest) are checked against `server.mjs` by `tests/gate-extension.test.ts`.

## Progress: one record for every browser

Progress lives in the tables service at `~/.local/state/tables/progress.json`, not inside one browser. The trainer works the same at `127.0.0.1:5170`, at `localhost:5170`, or from the `npm run dev` server, in Firefox or Zen.

- Each browser keeps a copy as an offline fallback.
- Saves send only the facts that changed.
- Copies are merged, never overwritten. Progress only grows: each fact keeps the copy with more attempts, and sessions are combined.

The gate reads the introduced facts from this file on the server, so nothing the challenge page sends can change which facts are eligible. It also remembers every fact it has ever seen practised (in `gate.json`), so resetting progress cannot make the challenge easier.

## Lifecycle

| Event | What locks it | Mechanism |
|---|---|---|
| Boot / restart | fresh process | grants live only in memory, never on disk |
| Login (the service lingers across logout) | `exec-once` in `hyprland.conf` | `POST /api/gate/revoke?reason=login` |
| Suspend / resume | the server itself | compares the wall clock with `CLOCK_MONOTONIC` on every check; a gap over 15 s revokes |
| Short suspends | `before_sleep_cmd` in `hypridle.conf` | `POST /api/gate/revoke?reason=suspend` |
| Clock changed | the server itself | same clock comparison; grants expire on the monotonic clock |
| 30 minutes | the server itself | expiry; open tunnels are cut within 1 s |

The challenge never appears before login or on the lock screen. It appears when you open a protected app afterwards.

## Commands

```sh
tables-gate status            # granted? time left, stage, recent events
tables-gate open [chatgpt]    # open the challenge page
tables-gate lock              # lock now
tables-gate logs [N]          # journal for tables.service
tables-gate restart

systemctl --user status tables stream
journalctl --user -u tables -f
```

After changing the app: `npm run build && systemctl --user restart tables`.

Browsers read their PAC at startup. After a PAC or policy change, restart Firefox/Zen; check it at `about:policies`.

## Troubleshooting

- **ChatGPT/Gemini show "The proxy server is refusing connections".** The gate is locked: pass the challenge. If this happens instead of a redirect, the extension isn't installed or active in that browser (`about:addons`). If it persists after passing, `tables-gate status`; if the service is down, `systemctl --user restart tables`.
- **Stream shows "Stream is not running".** `systemctl --user restart stream`.
- **Every site fails in Zen.** `gate.pac` is missing next to the Zen policy. Reinstall both files from `deploy/zen/`, or remove the extension directory to restore Zen's defaults:
  `sudo rm -r /var/lib/flatpak/extension/app.zen_browser.zen.systemconfig`
- **Changing the Firefox host list**:
  1. `sudo ~/.local/bin/deepwork-devtool unseal 30`
  2. Edit `GATED_HOSTS` in `~/.local/bin/deepwork`.
  3. `deepwork sync`
  4. `sudo ~/.local/bin/deepwork-devtool seal`

  Use the full path: `sudo`'s search path does not include `~/.local/bin`.

Backups of every file edited outside this repo are in `~/.local/state/tables/backup-2026-10-12/`.

## Known limits

- **Other browsers.** Only Firefox and Zen are gated. A full Chromium also exists at `~/.cache/ms-playwright/chromium-1234/` (installed for automated browser testing) and is not gated. Delete that directory if you don't need it. The DeepWork Warden closes unknown browsers only during study windows.
- **Scripting the challenge.** It can be solved by a script calling the API. The server refuses cross-site requests, but anything running locally as you can imitate the page. The gate raises the cost of a bypass; it is not a security boundary against yourself.
- **Root and file edits.** Root, or an edit to the locked browser policies, removes the gate, as with the rest of DeepWork.
- **The introduced-facts rule trusts the trainer's record.** Faking practice would require deliberately posting made-up progress to the API. Removing practice has no effect.
- **Stream offline shell.** If the gate service is down, a previously visited Stream tab may still show its cached interface (its service worker falls back offline), but videos cannot play.
